### 🧱 阶段一：重装底座与“金钟罩”防御（商业化基石）
**目标：在放出任何试用版之前，必须确保软件无法被轻易白嫖，且核心性能达到极致。**

*   **1. 商业级 DRM 授权体系（核心防线）：**
    *   **获取指纹：** 在 Rust 后端编写系统底层调用，抓取用户 CPU 序列号 + 主板 UUID，生成不可篡改的“机器特征码”。
    *   **非对称加密：** 引入 RSA 鉴权。前端提供输入框供用户填入 License（由服务器私钥签名），Rust 后端用写死的公钥进行验签解密，不匹配则在底层物理阻断“极速分割”等核心函数的执行。
    *   **前端混淆：** 在 Vite 中配置 `vite-plugin-obfuscator`，提高前端代码逆向门槛。
*   **2. 异步并发引擎与系统资源调度（极致性能）：**
    *   **并发重构：** 在 Rust 中引入 `tokio` 异步运行时，将原本串行的 FFmpeg 切割任务改造为多线程并发。90 分钟切 10 段的时间有望从十几秒压缩至 3-5 秒。
    *   **全局性能配置：** 在易剪的【全局设置】中新增“性能调度”面板。允许用户配置“最大并发任务数”和“FFmpeg 线程数”。Rust 后端读取此配置，避免在低配轻薄本上跑满 CPU 导致死机，实现主流视频软件的弹性资源管理。
*   **3. 无感平滑更新机制：**
    *   接入 Tauri Auto-Updater。配置 GitHub Releases 或阿里云 OSS 作为分发源。实现静默检测、增量下载、一键重启更新，为后续快速迭代打通管道。

---⏱️ 剖析二：计时模式（方案 B）的主流设计与破局
你提出的“借鉴录屏软件（OBS/Snagit）的操作流程”，是极其精准且专业的产品直觉！ 这正是解决“本地播放器/无法使用插件的环境下”盲打轴的最佳方案。

我为你详细设计这套 “易剪悬浮同步器 (EasyCut Sync Widget)” 的主流 UX：

1. 启动态（发令枪模式）：
   用户在易剪里点击“新建外部任务”，易剪主界面隐藏，屏幕边缘出现一个类似录屏软件的极简黑色悬浮窗（置顶且半透明）。
   悬浮窗上有三个大按钮：[▶ 启动同步] [⏸ 暂停同步] [⏹ 结束]，以及一个跳动的时间码 00:00.00。

2. 运行态（沉浸式打轴）：

对齐发令枪： 用户在自己的播放器（比如 VLC）里按下播放的同一瞬间，点击悬浮窗的 [▶ 启动同步]（或按全局快捷键 Ctrl+Space）。

沉浸盲打： 此时用户完全沉浸在自己的播放器中。当看到精彩画面时，按下易剪注册的全局系统快捷键 Ctrl+I 和 Ctrl+O。易剪根据悬浮窗秒表的时间，静默记录切片。每次按下，悬浮窗闪烁一下绿光并发出“滴”声，不打断用户看视频。

中途上厕所： 用户在播放器暂停，同时按下 Ctrl+Space，易剪的秒表也暂停。回来后继续。
